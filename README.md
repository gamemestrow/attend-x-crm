# Smart Attend

BUILD A COMPLETE INTERACTIVE HACKATHON PROTOTYPE

Build a polished, interactive and functional prototype for our Smart India Hackathon project.

PROJECT TITLE

Automated Student Attendance Monitoring and Analytics System for Colleges

PROJECT TEAM

The Innovators

---

1. PROJECT OBJECTIVE

We are building a prototype of a college attendance management system that replaces traditional manual roll-call attendance with a secure, time-bound, QR-based attendance workflow.

The system has two primary user roles:

1. Teacher

2. Student

There is NO Admin portal in this prototype.

The main purpose of this prototype is to demonstrate the complete working flow:

Teacher logs in → selects class and subject → configures attendance radius and QR validity → starts attendance → dynamic QR appears → students log in and scan the QR using the application's live camera scanner → system validates the student, QR, session, class, time and location → attendance is temporarily recorded → teacher sees real-time attendance → QR expires → remaining students are identified as absent → teacher reviews the complete attendance list → teacher submits the attendance → attendance becomes final and is stored → student can view attendance history by date and subject.

This is an internal hackathon prototype, not a production-ready enterprise system.

Prioritize:

- Functional demonstration

- Clear user flow

- Good UI/UX

- Realistic interaction

- Clean architecture

- Easy future Supabase integration

Do NOT spend unnecessary development effort on:

- Advanced AI

- Face recognition

- Complex authentication

- Excessive animations

- 3D models

- Heavy graphics

- Unnecessary backend complexity

2. CORE PRODUCT IDEA

The system uses a dynamic, time-bound QR code generated by a teacher.

The teacher decides how long the QR code should remain valid.

Available durations:

- 10 seconds

- 15 seconds

- 20 seconds

- 30 seconds

Example:

Teacher selects:

QR Validity: 15 seconds

The system generates a unique QR token.

Students who are:

- logged in,

- members of the correct class,

- within the teacher's configured attendance radius,

- scanning during the valid session,

- and have not already marked attendance,

can successfully mark attendance.

The QR itself remains visible after expiration, but becomes clearly marked as:

EXPIRED

An expired QR must not be accepted.

The teacher can then generate a new QR without leaving the current page and without refreshing the page.

22. GENERATE NEW QR

When the teacher clicks:

Generate New QR

do NOT:

- Refresh the page

- Navigate to dashboard

- Open a new page

- Reset the entire form

- Lose current attendance information

Instead:

1. Generate a new token.

2. Generate a new QR.

3. Create/update the appropriate session token information.

4. Reset countdown.

5. Apply the selected QR duration.

6. Display the new QR immediately.

7. Continue on the same attendance page.

The previous QR token must remain invalid.

This is important for the dynamic QR security model.
